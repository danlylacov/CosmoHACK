# Методика расчёта траектории и освещённости МКС

Документ описывает орбитальный контур: источник эфемерид, перевод в географические координаты, определение тени и воспроизведение движения на глобусе. Распространение орбиты (SGP4/SDP4) на клиенте не выполняется.

## 1. Назначение контура

1. Показать положение МКС и отслеживаемых объектов на интервале планирования.
2. Отметить интервалы тени (условие работ, не механизм риска).
3. Связать положение со сближениями (MMOD): дистанция, TCA, порог критичности.

Механизмы риска в системе: космическая погода (SW) и MMOD. Освещённость в оценку риска не входит.

## 2. Разделение ответственности

| Задача | Исполнитель | Результат |
| --- | --- | --- |
| TLE → положение | CosmoHACK Orbit API<br>POST /api/v1/orbits/positions | выборки ISS и объектов в TEME, км |
| Оценка сближения | CosmoHACK Orbit API<br>POST /api/v1/conjunctions/distances | distance_km, TCA, критические интервалы |
| TEME → широта, долгота, высота | клиент | географические координаты |
| Тень / терминатор | клиент | in_shadow, интервалы тени |
| Отображение во времени | клиент | интерполяция между выборками |

Горизонт запроса совпадает с периодом поиска в форме: [*t*₀, *t*₀ + *T*], *T* ∈ [1, 24] ч. Все метки времени – UTC.

При статусе STALE (эпоха элементов далека от окна) расчёт живой орбиты отклоняется. Режим «Сейчас» соответствует текущей эпохе TLE. Геометрия после успешного ответа – operational.

## 3. Исходные данные

– Система: TEME (True Equator, Mean Equinox).  
– Положение: *r* = (*x*, *y*, *z*) в километрах.  
– Шаг выборки API: как правило **60 с**.  
– Идентификация объекта: NORAD ID, иначе имя.

Расстояние между телами считается в TEME:

$$d = \| r_A - r_B \|$$

Поворот к ECEF ортогонален, поэтому *d* в ECEF совпадает.

## 4. TEME → географические координаты

Цель – широта φ, долгота λ, высота *h* для карты и глобуса.

### 4.1. GMST

$$JD = t_{\mathrm{unix}} / 86\,400\,000 + 2\,440\,587{,}5$$

$$\theta^\circ = \bigl(280{,}46061837 + 360{,}98564736629 \cdot (JD - 2\,451\,545{,}0)\bigr) \bmod 360$$

θ – среднее гринвичское звёздное время. UT1−UTC, нутация и EOP не вводятся.

### 4.2. TEME → ECEF (поворот вокруг оси *z*)

$$x_E = x \cos\theta + y \sin\theta$$

$$y_E = -x \sin\theta + y \cos\theta$$

$$z_E = z$$

### 4.3. Сферическая Земля *R* = 6371 км

Эллипсоид WGS-84 не используется.

$$r = \sqrt{x_E^2 + y_E^2 + z_E^2}$$

$$\varphi = \arcsin(z_E / r)$$

$$\lambda = \operatorname{atan2}(y_E, x_E)$$

$$h = r - R$$

φ, λ – в градусах, *h* – в километрах. Горизонтальная погрешность модели – порядка километров. Для индикации положения и тени на интервале часов это приемлемо; для баллистической экспертизы – нет.

## 5. Траектории объектов

На каждой выборке:

1. Строится точка МКС: время, φ, λ, *h*, признак тени.
2. Перебираются screened_objects.
3. Объект с *d* < 5 км до ISS классифицируется как элемент комплекса МКС и исключается (стыковка / модуль).
4. Прочие объекты образуют отдельные треки; у каждой точки хранится *d* до ISS.
5. closest_approach – минимум *d* по окну среди неисключённых объектов.

Интервалы тени – непрерывные отрезки, где МКС в тени, в виде пар UTC [*t*_in, *t*_out].

## 6. Освещённость

Подсолнечная точка задаётся аналитически, без эфемерид JPL и уравнения времени:

$$\delta = 23{,}44^\circ \cdot \sin\bigl(2\pi \, (\mathrm{doy} - 81) / 365\bigr)$$

$$\lambda_\odot = -15^\circ \cdot (t_{\mathrm{UTC}} - 12),\quad \lambda_\odot \in [-180^\circ, 180^\circ]$$

Зенит Солнца *z* в точке (φ, λ) – угол между местной вертикалью и направлением на Солнце.

| Критерий | Условие |
| --- | --- |
| МКС в тени | *z* > 96° |
| День → ночь на глобусе | плавный переход при *z* ∈ [86°, 108°]<br>(гражданские–астрономические сумерки) |

Порог 96° шире геометрического лимба и частично учитывает диск Солнца; рефракция не моделируется.

## 7. Сближения (MMOD)

После ответа conjunctions/distances график и метрики miss/TCA берутся из этого API. Ряд дистанций по screened_objects – резерв до получения сводки сближений.

Если TCA из summary не попадает на 60-секундную сетку, точка (*t*_TCA, *d*_min) добавляется в ряд явно.

Индикатор риска по дистанции (порог *d*_crit задаётся в форме, по умолчанию 5 км):

$$\rho(d) = \bigl(1 + \exp((d - d_{\mathrm{crit}}) / (d_{\mathrm{crit}} / 2))\bigr)^{-1}$$

ρ(0) = 1, ρ(*d*_crit) = 0,5, ρ → 0 при *d* ≫ *d*_crit. Вероятность столкновения Pc не вычисляется и не подставляется.

## 8. Воспроизведение на глобусе

Время сцены – часы от *t*₀. Положение между выборками: линейная интерполяция φ и *h*; λ – по кратчайшей дуге (учёт перехода ±180°).

Между узлами 60 с траектория – хорда, не кеплерова дуга.

Вертикальный масштаб на сфере: высота умножается на 8. Это только читаемость орбиты ~400 км, не физическая высота.

## 9. Границы применимости

| Принято | Не входит в контур |
| --- | --- |
| Эфемериды Orbit API (TEME) | SGP4 на клиенте |
| Сферическая Земля 6371 км | WGS-84, геоид, EGM |
| Среднее GMST | UT1, нутация, polar motion |
| Аналитическое Солнце | DE440 / JPL |
| Тень по зениту | рефракция, форма Земли |
| Miss и TCA API сближений | CDM, ковариация, Pc |
| Отсев *d* < 5 км как ISS-associated | каталог модулей МКС |
