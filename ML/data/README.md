# Данные космической погоды

Загрузка, конвертация и добавление в накопленный датасет одной командой из любого каталога:

```bash
/Users/ivacshsergey/hack/data/run.sh --date 2026-09-18
```

Другие варианты запуска из каталога `data`:

```bash
./run.sh --start 2026-09-18 --end 2026-09-19
./run.sh --date 2026-09-18 --strict
./run.sh --date 2026-09-18 --plan-only
./run.sh --date 2026-09-18 --out /tmp/weather-experiment
./run.sh --help
```

В диапазоне `--start` / `--end` обе даты включены. Поддерживаются параметры загрузчика; `--out` здесь означает **каталог накопленного датасета**, по умолчанию `data/datasets`. Относительный путь считается от текущего каталога терминала.

## Результат

После завершения в каталоге датасета остаются только два обычных файла:

- `results.csv` — таблица для модели с шагом 30 минут и ключом `time_utc`.
- `results.json` — накопленные исходные измерения, описания показателей и границы рядов.

Они обновляются при каждом успешном запуске. Версии, манифесты, отчёты и символические ссылки не создаются. Временные файлы удаляются автоматически; блокировка одновременной записи не создаёт отдельного файла.

## Инструменты

```text
data/
  run.sh
  datasets/
    results.csv
    results.json
  tools/
    update_dataset/             # общий запуск и объединение JSON
    download_and_convert/       # выгрузка + конвертация
    append_data_tool/           # объединение CSV
    space_weather_downloader/   # получение данных
    space_weather_model_data/   # JSON → получасовой CSV
```

Единый запуск вызывает `download_and_convert`, затем `append_data_tool` и потоковое объединение JSON. Все компоненты и окружение загрузчика находятся в `data/tools`; от прежних папок в корне проекта этот набор не зависит.

## Правила обновления

- При совпадении времени **вся свежая строка CSV заменяет старую**, включая пустые значения; правило задаёт `append_data_tool`. Обновляйте тем же набором `--sources`: выбор только части факторов очищает остальные колонки обновляемых окон.
- Повтор той же даты не создаёт дубли строк. История остальных дат сохраняется.
- Отсутствие дат между выгрузками не заполняется измерениями. JSON хранит `period.included_ranges_utc`; копия конвертера учитывает эти диапазоны и не создаёт фиктивных строк между ними.
- CSV — готовый датасет для модели; JSON — накопленные исходные измерения с границами рядов. При изменении набора факторов повторная конвертация JSON может представлять отсутствующий `_count` как `0`, тогда как append CSV оставляет пустую ячейку. Побайтовое равенство повторного экспорта не обещается.
- Загрузка, конвертация и объединение выполняются во временном каталоге. Ошибка до публикации и `--strict` с неполной выгрузкой сохраняют прежние файлы.
- Без `--strict` допускаются частичные данные по правилам загрузчика. Полностью пустая выгрузка не публикуется. Ноль, реально записанный в измерениях, допустим.
- Одновременно допускается один процесс обновления на каталог датасета.
- `--plan-only` и `--help` ничего не скачивают и не обновляют датасет.

Каждый итоговый файл заменяется атомарно после подготовки обоих; обычная ошибка публикации вызывает откат. Два файла не образуют единую атомарную транзакцию: согласованную пару читайте после успешного завершения команды. История предыдущих выгрузок не сохраняется.

## Проверки

Тесты общего инструмента и объединения JSON из каталога `data`:

```bash
python3 -B -m unittest discover -s tools/update_dataset/tests -v
```

Для больших периодов удобнее запускать обновление по дням или небольшими диапазонами: загрузчик и CSV-конвертер обрабатывают свежую выгрузку целиком, а накопленный JSON объединяется потоково.
