# Подготовка данных для модели

Для загрузки с добавлением в общий датасет используйте [единый инструмент](../../README.md). Ниже — отдельный запуск этого компонента.

Один скрипт, Python 3.9+, без внешних зависимостей.
Вход — `results.json` из `space_weather_downloader`.

Запуск из `/Users/ivacshsergey/hack/data/tools`:

```bash
python3 space_weather_model_data/series_to_csv.py ../datasets/results.json /tmp/series.csv
```

Можно передать любой путь к входному JSON и выходному CSV. Каталог результата
создаётся автоматически; существующий CSV перезаписывается.

## Измерения

`series.csv`: `time_utc` и колонки с именами `series[].metric`.
Для частых измерений рядом добавляются `<metric>_min`, `<metric>_max`,
`<metric>_last`, `<metric>_count`; исходная колонка `<metric>` содержит среднее.
Время — начало окна `[time_utc, time_utc + 30 минут)` в UTC.
Для обычной выгрузки включены все окна от `period.start_utc` до исключённой границы
`period.available_until_exclusive_utc`, даже полностью пустые. В накопленном JSON
`period.included_ranges_utc` ограничивает строки реально добавленными периодами:
список интервалов `start_utc` / `end_exclusive_utc` с границами на шаге 30 минут.
Промежутки между отдельно загруженными датами не создают пустые строки;
пустой список даёт только заголовок CSV.
Если граница периода не кратна 30 минутам, крайнее окно содержит только
доступную часть периода.

- Частые измерения усредняются арифметически внутри окна. Дополнительно
  рассчитываются минимум, максимум, последнее непустое значение по времени
  измерения и количество непустых исходных точек после удаления дублей.
  Эти четыре статистики используют точки с интервалом меньше 30 минут;
  записи без указанного интервала считаются отдельными частыми измерениями.
  При интервалах от 30 минут дополнительные колонки не создаются.
- Более длинные интервалы повторяются в пересекающихся окнах. Их границы
  берутся из `quality.interval_end_utc` / `quality.interval_seconds`;
  для `geomagnetic_kp` и `geomagnetic_ap` интервал равен трём часам.
- Без указанного интервала запись считается отдельным измерением.
  Расстояние до следующей записи не используется как длительность:
  пропуск не продлевает предыдущее значение.
- Если фактор есть в нескольких рядах, сначала рассчитывается среднее
  каждого ряда в окне, затем среднее этих результатов с равными весами.
  Минимум, максимум и количество учитывают все исходные частые точки этих
  рядов. Если на последнюю временную отметку приходится несколько значений,
  `<metric>_last` содержит их среднее.
- Точные дубли времени, интервала и значения внутри ряда исключаются.
  `null`, NaN и Infinity не участвуют в статистиках. В пустом окне количество
  равно `0`, остальные статистики пустые. Нули и отрицательные числа сохраняются.

CSV содержит только время и значения. Сокращённый `results.json` содержит только данные для этих преобразований;
единицы, происхождение и приборные флаги в нём больше не сохраняются.
`quality` содержит границы и длительности интервалов. При обрезке старого
интервала новым периодом `original_interval_seconds` сохраняет исходную
длительность: короткий остаток часового индекса не становится частым измерением.
Дополнительная фильтрация чисел по флагам качества здесь не выполняется.
Время измерения не заменяет время публикации при историческом прогнозе.

