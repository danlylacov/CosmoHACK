# SEPNET для космической погоды

Обучаемая адаптация [SEPNET-PRISM](https://arxiv.org/abs/2606.14440v2)
под наши CSV: **72 часа истории → 64 получасовых окна** на следующие 32 часа.
Прогнозируются средние и максимальные потоки протонов >10, >50 и >100 МэВ,
интервалы и совместная вероятность превышения порогов.

## Запуск

Python 3.9+, из корня проекта:

```bash
python3 -m pip install -r models/sepnet/requirements.txt
python3 models/sepnet/train.py
python3 models/sepnet/infer.py
```

Данные: первый каталог с CSV из `models/sepnet/data/`, `models/lstm/data/`,
`space_weather_model_data/output/`. Подкаталоги читаются рекурсивно.
Можно передать `--data /path/to/csv` или путь к файлу. Формат обучения
и инференса одинаков: `time_utc` и числовые колонки конвертера.
Будущие значения не нужны; стандартная история — 144 завершённых окна.

Веса и отчёт: `models/sepnet/artifacts/`; результаты: `models/sepnet/output/`.
Веса LSTM не перезаписываются. Для отдельных экспериментов задайте `--output`,
для загрузки выбранных весов — `--checkpoint`. Прогноз начинается после
последнего завершённого окна. Другое время: `--origin ...` или `--origin now`.

```bash
python3 models/sepnet/train.py --smoke --data space_weather_model_data/output
python3 models/sepnet/infer.py --smoke --data space_weather_model_data/output
```

`--smoke`: до двух эпох, история 6 часов, отдельные веса `artifacts/smoke/`;
неизвестные будущие цели маскируются. Вероятности, интервалы, решения и
необученные горизонты остаются `null`. Полный список параметров: `--help`.

## Модель и данные

```text
72 часа → три суточные сводки min/mean/max
           ├→ BiLSTM → Transformer ───────────────┐
           └→ последняя сводка + последнее окно → MLP → объединение → потоки + событие
```

Сводки строятся по нормализованным признакам, маскам пропусков и возрасту
наблюдений. Двунаправленность и внимание работают только внутри прошлой истории.
По умолчанию модель учит поправку к последним наблюдаемым потокам в `log1p(pfu)`;
необученная residual-голова начинает с persistence. `--no-residual` возвращает
прежнюю прямую голову. Квантили упорядочены, потоки неотрицательны, `mean <= max`.

Подготовка данных, обучение и калибровка общие с [LSTM](../lstm/README.md):

- `coverage_fraction` **не требуется**. Событие — наблюдаемый максимум >10 МэВ
  от 10 pfu или >100 МэВ от 1 pfu; оба известных максимума ниже порогов дают
  отрицательную метку. Недостаточные наблюдения без превышения — неизвестную.
- `--features engineered` по умолчанию: все наблюдаемые числовые колонки,
  включая EUV, MgII и индексы; причинные сводки и изменения за 1/6/24 часа,
  циклические признаки времени. Варианты сравнения: `all` и `core`.
- Полностью отсутствующие в тренировочной части каналы и их `_count`
  исключаются. Поздние differential-колонки текущего архива не могут получить
  обученное влияние из одной лишь тестовой части.
- Kp/ap сдвигаются на 5 получасовых строк, Hp60/ap60 — на одну, суточные
  индексы/F10.7/число пятен — на 48. Это учитывает завершение интервала,
  но не гарантирует фактическое время публикации. Текстовые прогнозы не используются.
- Весь архив распределяется по времени 70/10/10/10; последние три части
  служат выбору эпохи, калибровке и проверке, не обновлению весов.
  Обучающие окна перемешиваются; нормализация обучается только на train.
- Интервалы калибруются по четырём диапазонам горизонтов с минимумом
  **10 начал прогноза** на диапазон, без выдачи коррелирующих окон за независимые.
- Откалиброванная `p_adverse` сравнивается с порогом для `eva_allowed`,
  если пройдены проверки данных и интервалов. Проверка Brier score сохраняется
  в отчёте обучения и не блокирует решение. Экспериментальная вероятность
  сама по себе не означает подтверждённое качество прогноза.
  Экспериментальные интервалы также могут содержать числа, но отмечаются
  `unvalidated_intervals` и не разрешают принятие решения.

`--event-weight` по умолчанию `0.1`, `--learning-rate` — `0.0003`.
Отчёт сравнивает модель с persistence отдельно на событиях и спокойных окнах.
Календарного ограничения обучения и запрета инференса по дате весов нет.
CSV не подтверждает публикацию и приборное качество: режим `retrospective_csv`.
Это прогноз внешней космической погоды, а не расчёт дозы или допуск к ВКД.

В статье два суточных входа, одна метка события на 24 часа и будущие максимумы
протонов >10 МэВ/X-ray. Здесь три дня, три протонных канала, получасовая траектория
и residual-голова. Нет SHARP/SMARP, вспомогательной рентгеновской цели,
focal loss или поэтапного включения регрессии. Это адаптация, не воспроизведение
авторских весов или опубликованного качества.

```bash
python3 -m unittest discover -s models/sepnet -v
```
