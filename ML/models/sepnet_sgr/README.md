# SEPNET-SGR

История **72 часа** → прогноз **32 часа: 64 окна по 30 минут**.
Выход: потоки протонов, рентгеновский поток, Kp, уровни S/G/R и решение о ВКД.

## Обучение

CSV формата `space_weather_model_data/output` кладите в `models/sepnet_sgr/data/`.
Если папка пуста, обучение ищет данные в `models/sepnet/data`, затем
`models/lstm/data`, затем `space_weather_model_data/output`. Другой путь: `--data ПУТЬ`.

Из корня проекта:

```bash
python3 -m pip install -r models/sepnet_sgr/requirements.txt
python3 models/sepnet_sgr/train.py
```

Веса: `models/sepnet_sgr/artifacts/model.pt`; метрики — в поле `report` внутри чекпоинта.
Нужен чекпоинт именно SEPNET-SGR. Для короткого архива доступен `train.py --smoke`:
веса сохраняются в `artifacts/smoke/model.pt`, решение о ВКД всегда `null`.

## Инференс

Обязательны только три аргумента:

```bash
python3 models/sepnet_sgr/infer.py \
  --checkpoint models/sepnet_sgr/artifacts/model.pt \
  --origin 2026-09-05T01:00:00Z \
  --data models/lstm/data
```

- `--checkpoint` — путь к весам; настройки модели берутся из них.
- `--origin` — ISO-дата на границе получаса (`:00`/`:30`); без часового пояса — UTC.
  Значение `now` означает текущую границу получаса.
- `--data` — CSV-файл или каталог с CSV.

Измерения после заданного времени отсекаются. Если дата позже последнего наблюдения,
**прогноз начинается от конца последнего измеренного окна**, на следующие 32 часа.
Фактическое начало — `forecast_origin_utc`; пустой хвост CSV игнорируется.
Если обычный инференс завершается ошибкой, используется аварийный режим ниже.

Необязательно: `--output ПАПКА` — куда сохранить результат; `--cutoff ДАТА` —
дополнительное ограничение доступных измерений; `--policy ФАЙЛ` — заменить политику из весов.

## Результат и ВКД

Файлы: `models/sepnet_sgr/output/forecast.json` и `forecast.csv`.
В каждом окне: `*_pred`, `*_lower`, `*_upper`, уровни S/G/R, `eva_allowed`, `reason`.

S считается по максимуму протонов ≥10 МэВ, R — по максимуму `solar_xray_flux_long`,
G — по трёхчасовому Kp. Пороги — в [scales.py](scales.py).
Уровень `0` — ниже первого порога, `null` — данных недостаточно.

По умолчанию ВКД запрещается при **S≥1 или G≥1 или R≥1**. Пороги настраиваются
в [policy.json](policy.json); чтобы применить изменения к готовым весам, передайте `--policy`.
`p_adverse` — вероятность S≥1 или G≥1 или R≥1; решение ВКД принимается по уровням.

Это правило прототипа, не официальный допуск к ВКД.
Качество и ограничения конкретных весов оценивайте по отчёту обучения.

## Аварийный режим

При исключении, ошибке загрузки весов/зависимостей или некорректных числах:
`прогноз = последнее значение + N(0, 0.02 × дисперсия признака)`.
Статистика считается отдельно для каждой величины в физических единицах по CSV до cutoff.
Если CSV недоступен, используются резервная статистика или исходные данные обучения.
Рядом с весами сохраняется `model.fallback.json`; переносите его вместе с `model.pt`.
Шум центрирован до ограничений: потоки ≥0, максимум ≥среднего, Kp от 0 до 9.
Kp одинаков внутри трёхчасового блока. S/G/R и ВКД пересчитываются по этим значениям.
В `reason` отмечаются fallback и тип ошибки; вероятность и интервалы — `null`.
Если нет ни доступных данных, ни подходящего по дате резерва, выдаются 64 окна с `null`.
Если сохранить файлы невозможно, аварийный JSON выводится в stdout, ошибка — в stderr.
