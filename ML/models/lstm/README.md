# LSTM для космической погоды

LSTM читает **72 часа истории** и выдаёт **64 получасовых окна** на 32 часа.
Для протонов >10, >50 и >100 МэВ прогнозируются среднее и максимум окна,
интервалы и вероятность события. Это модель внешней космической погоды,
без расчёта орбиты или дозы космонавта.

## Запуск

Python 3.9+, из корня проекта:

```bash
python3 -m pip install -r models/lstm/requirements.txt
python3 models/lstm/train.py
python3 models/lstm/infer.py
```

CSV положите в `models/lstm/data/`; подкаталоги читаются рекурсивно.
Без своих CSV используется `space_weather_model_data/output/`.
Формат обучения и инференса одинаков: `time_utc` и числовые колонки из
`space_weather_model_data/series_to_csv.py`. Время обозначает начало окна
`[time_utc, time_utc + 30 минут)`. Будущие наблюдения для инференса не нужны.
Совпадающие записи объединяются; конфликтующие значения вызывают ошибку.
Пропуски временных окон сохраняются.

```bash
python3 models/lstm/train.py --data /path/to/csv --epochs 30
python3 models/lstm/infer.py --data observations.csv --origin 2024-05-15T12:00:00Z
```

По умолчанию инференс начинается после последнего завершённого окна данных;
`--origin now` задаёт текущее время. `--cutoff` исключает ещё недоступные окна.
Календарного ограничения обучения или запрета инференса по дате весов нет.
Все параметры: `--help`.

Веса и отчёт: `artifacts/model.pt`, `artifacts/training_report.json`.
Результат: `output/forecast.json` с метаданными и `output/forecast.csv` с 64 окнами.
Чтобы сохранить другой эксперимент, задайте `--output`; при инференсе — `--checkpoint`.

Короткий технический прогон:

```bash
python3 models/lstm/train.py --smoke --data space_weather_model_data/output
python3 models/lstm/infer.py --smoke --data space_weather_model_data/output
```

`--smoke` использует 6 часов истории, до двух эпох и отдельные веса
`artifacts/smoke/model.pt`. Неизвестные будущие цели маскируются;
необученные горизонты, вероятности, интервалы и решения остаются `null`.

## Данные и признаки

**`coverage_fraction` не требуется.** Метка строится по наблюдаемым максимумам:
`max(J_>10) >= 10 pfu` или `max(J_>100) >= 1 pfu` означает событие.
Если оба максимума известны и ниже порогов, метка равна нулю.
Если максимум отсутствует и известного превышения нет, метка неизвестна.
Это разметка наблюдений CSV, а не подтверждение отсутствия события в пропусках.
Объединённый по приборам `_count` используется как признак, а не доля покрытия.

Наборы признаков выбираются через `--features`:

- `core`: протонные, электронные и рентгеновские потоки, ветер и магнитное поле.
- `all` (по умолчанию): все числовые колонки с наблюдениями в тренировочной части, включая
  EUV, MgII, AE/AL/AU, SYM-H, геомагнитные индексы, F10.7 и число пятен.
- `engineered`: `all`, среднее/стандартное отклонение/изменение
  за 1, 6 и 24 часа для целевых потоков, X-ray, скорости и плотности ветра,
  Bz и величины магнитного поля; синус/косинус времени суток и дня года.

На текущем архиве: 95 признаков в `core`, 172 в `all`, 284 в `engineered`;
число меняется вместе с набором наблюдаемых колонок.

Признаки, появившиеся только после тренировочной части, не обучаются и не
добавляются при инференсе. `_count` полностью пустого базового канала также
исключается. В текущем архиве это относится к поздним differential-каналам.

Kp/ap сдвигаются на 5 получасовых строк, Hp60/ap60 — на одну: агрегат
используется после завершения соответствующего интервала. Суточные индексы,
число пятен и F10.7 сдвигаются на сутки. Эти сдвиги учитывают интервалы,
но **не гарантируют доступность публикации**: CSV не сохраняет её время.
Текстовый `forecasts.csv` не используется.

Нормализация и список колонок определяются только по тренировочной части.
Пропуски имеют маски и возраст; заполнение идёт из прошлого до 48 часов.
Производные признаки также используют только прошлые строки.

## Обучение и проверка

Весь переданный архив распределяется по времени: **70% обучение, 10% выбор
эпохи, 10% калибровка, 10% внутренняя проверка**. Последние 30% не участвуют
в обновлении весов. Цели не пересекают границы частей; калибровочные и тестовые
прогнозы начинаются каждые 32 часа. Порядок обучающих окон перемешивается,
порядок измерений внутри каждого окна сохраняется.

По умолчанию сеть учит **поправку к последним наблюдаемым средним и максимумам**
в `log1p(pfu)`. Такая residual-голова начинает с прогноза persistence.
`--no-residual` включает прежний прямой прогноз. Неотрицательность,
порядок квантилей 0.1/0.5/0.9 и `mean <= max` обеспечены моделью.
Точечный прогноз — медианная оценка будущей статистики окна.

Два слоя LSTM, скрытый размер 64, Adam, до 20 эпох с ранней остановкой.
`--learning-rate` по умолчанию `0.001`, `--event-weight` — `0.1`:
взвешенная бинарная ошибка события добавляется к квантильной ошибке потоков.
Отчёт сравнивает модель с persistence отдельно на событиях и спокойных окнах.

Интервалы калибруются по диапазонам 0–6, 6–12, 12–24 и 24–32 часа.
Одна точка начала прогноза даёт один максимальный остаток на диапазон;
минимум — **10 начал прогноза**, а не 10 коррелирующих получасовых окон.
Откалиброванные интервалы могут быть экспериментальными; отдельная проверка
покрытия определяет подтверждённость, а не наличие чисел в результате.

`p_adverse` может содержать откалиброванную **экспериментальную** вероятность,
даже если она не прошла проверку качества. Проверка качества вероятности
сохраняется в отчёте обучения и не блокирует `eva_allowed`.
Аналогично экспериментальные интервалы отмечаются `unvalidated_intervals`
и не разрешают принятие решения.
Подтверждение вероятности требует улучшения Brier score относительно частоты
событий не менее чем на 1%, достаточных данных и событий согласно `policy.json`.
Одного наблюдаемого эпизода достаточно для исследовательской калибровки,
но недостаточно для вывода о надёжности на будущих штормах.

`eva_allowed` определяется сравнением доступной откалиброванной вероятности
с порогом после проверок данных и интервалов. Порог 0.1 — исследовательская настройка, не эксплуатационный
допуск к ВКД. Политика сохраняется в весах; её изменение требует переобучения.

CSV не сохраняет версии и приборные флаги: результат обозначен
`retrospective_csv`. Зависимость окон во времени и малое число независимых
штормов ограничивают выводы из внутренней проверки; внешняя оценка необходима.

Архитектурная основа: [Yi et al., 2025](https://arxiv.org/abs/2510.05399).
Прямые выходы, три канала, квантили, residual-голова и классификация — адаптация.

```bash
python3 -m unittest discover -s models/lstm -v
```
