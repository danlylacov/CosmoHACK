# Выгрузка космической погоды и конвертация в CSV

Для загрузки с добавлением в общий датасет используйте [единый инструмент](../../README.md). Ниже — отдельный запуск этого компонента.

```bash
/Users/ivacshsergey/hack/data/tools/download_and_convert/run.sh --date 2024-05-10
```

Принимает параметры текущего `space_weather_downloader/download_space_weather.py` и передаёт их без изменений. Зависимости устанавливает существующий `space_weather_downloader/run.sh`; отдельное окружение не создаётся. Работает из любого каталога.

```bash
./run.sh --start 2024-05-01 --end 2024-05-03 --sources hpo,solar-indices --out ./output
./run.sh --date 2024-05-10 --sources hpo --strict --out ./output
./run.sh --help
./run.sh --date 2024-05-10 --plan-only
```

`--out` — каталог обоих файлов. Относительный путь считается от текущего каталога терминала. По умолчанию, как у загрузчика, файлы находятся в `space_weather_downloader/`:

- `results.json` — результат загрузчика.
- `results.csv` — результат существующего `space_weather_model_data/series_to_csv.py`.

CSV имеет шаг 30 минут и правила существующего конвертера: показатели с одинаковым `metric` объединяются между рядами; для частых измерений добавляются min/max/last/count. Полные исходные ряды остаются в JSON. Этот инструмент не меняет правила агрегации и фильтрации конвертера.

`--help` и `--plan-only` не создают CSV. При ошибке загрузки старый JSON не конвертируется. При ошибке конвертации предыдущий CSV остаётся на месте: новый файл заменяет его только после успешного завершения конвертера. При неполной выгрузке с `--strict` свежий JSON всё равно преобразуется, а код завершения остаётся 2. Без `--strict` полнота определяется правилами загрузчика; успешная конвертация не означает отсутствие пропусков.

Также можно запустить напрямую: `python3 download_and_convert.py <параметры>`.
