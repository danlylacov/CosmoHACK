# Данные космической погоды для модели

Для загрузки с добавлением в общий датасет используйте [единый инструмент](../../README.md). Ниже — отдельный запуск этого компонента.

Загрузчик создаёт один `results.json`, совместимый со скриптом `space_weather_model_data/series_to_csv.py`. В нём только поля, необходимые для получения `series.csv`. Числа не округляются, временные ряды не усредняются заранее.

## Запуск

Нужен Python 3.9–3.12 с OpenSSL 1.1.1+; рекомендуется 3.11. `run.sh` при первом запуске создаёт `.venv` и устанавливает зависимости из `requirements.txt`.

```bash
cd space_weather_downloader
./run.sh --date 2024-05-10
./run.sh --start 2024-05-01 --end 2024-06-30
./run.sh --start 2023-01-01 --end 2025-12-31 --sources particles,kp,omni,hpo,solar-indices
./run.sh --date 2024-05-10 --profile light
./run.sh --date 2024-05-10 --plan-only
```

Даты включены, время UTC. Без дат выбираются текущие сутки. `--out ./data` меняет путь результата на `./data/results.json`; по умолчанию он находится рядом со скриптом.

Период обрабатывается недельными частями: память загрузчика не растёт пропорционально всему многолетнему ряду. Ряды разных недель записываются отдельными элементами `series`, с непересекающимися интервалами измерений. Это сохраняет результат конвертера. Длинные временные интервалы индексов заканчиваются на границах UTC-суток и не пересекают недельные части.

Исходные файлы находятся в системном временном каталоге и удаляются после завершения или ошибки. Суточные продукты освобождаются после обработки части; годовые OMNI/Kp переиспользуются внутри запуска. Постоянного кеша нет. Запись `results.json` атомарная: ошибка экспорта сохраняет предыдущий результат.

## Состав результата

```json
{
  "period": {
    "start_utc": "2024-05-10T00:00:00Z",
    "available_until_exclusive_utc": "2024-05-11T00:00:00Z"
  },
  "series": [
    {
      "metric": "geomagnetic_hp60",
      "samples": [
        {
          "time_utc": "2024-05-10T00:00:00Z",
          "value": 4.0,
          "quality": {
            "interval_seconds": 3600,
            "interval_end_utc": "2024-05-10T01:00:00Z"
          }
        }
      ]
    }
  ]
}
```

Файл записывается без отступов. У обычных измерений есть только `time_utc` и `value`. `quality` сохраняется только для явной длительности интервала GFZ; она нужна для повторения часовых/суточных индексов в получасовых окнах CSV. Для Kp/ap трёхчасовой интервал уже задан в конвертере.

`null` остаётся пропуском; нули и отрицательные значения сохраняются. Раздельные ряды поставщиков/спутников не склеиваются, хотя их подписи удалены: конвертер сначала считает среднее каждого ряда, затем среднее между рядами. Удалять дублирующий ряд целиком или смешивать его с другим нельзя без изменения весов и статистик.

В JSON нет событий, спектральных массивов, URL, SHA, описаний, единиц, технических отчётов и флагов качества приборов. Он предназначен для этих конвертеров, которые и раньше не фильтровали значения по приборным флагам. Для научной интерпретации и проверки исторической доступности данных этот сокращённый файл не заменяет документацию источников.

## Что скачивается

По умолчанию — все перечисленные группы; `--sources` принимает список через запятую.

| Группа | Содержание |
|---|---|
| `particles` | Интегральные потоки протонов/электронов ISWA и текущие SWPC |
| `kp` | Трёхчасовые Kp/ap GFZ |
| `omni` | Архивные магнитное поле, солнечный ветер, AE/AL/AU/SYM-H |
| `solar-wind` | Текущий солнечный ветер RTSW |
| `xrs` | Два архивных рентгеновских канала GOES |
| `hpo` | Hp30/ap30/Hp60/ap60 |
| `solar-indices` | Суточные Ap/Cp/C9/SN/Fobs/Fadj |
| `live-spectra` | Только текущие дифференциальные потоки SWPC как числовые ряды |
| `live-xrs` | Текущие рентгеновские потоки; также выбирает архив `xrs` |
| `euv` | Только девять числовых каналов EUVS/Mg II из архивных NetCDF |

DONKI, alerts, EHIS и архивные MPSH/SGPS-спектры удалены из загрузчика: они не использовались при построении этих CSV. EUV/XRS NetCDF остаются необходимыми источниками числовых рядов; полные массивы, дополнительные переменные и флаги не экспортируются.

`--profile light` или `--skip-netcdf` исключают `xrs` и `euv`. Оперативные ленты имеют короткую глубину. Дифференциальные каналы `live-spectra` недоступны за произвольные исторические годы; удалённые архивы раньше тоже не превращались в такие `series`.

Прочие параметры: `--workers 1..8`, `--timeout 30`, `--satellites 16 17 18 19`, `--strict`. Ошибки и статус выводятся в консоль. `--strict` сохраняет доступные данные, но возвращает код 2 при ошибках или неполноте выбранных источников. Неполнота не означает благоприятную космическую погоду.

## Получение series.csv

Из родительского каталога:

```bash
python3 space_weather_model_data/series_to_csv.py space_weather_downloader/results.json space_weather_model_data/output/series.csv
```

Сами конвертеры пока читают JSON целиком через `json.load`; ограничение памяти недельной частью относится к загрузчику. Размер итогового JSON и память конвертации по-прежнему растут с периодом.
